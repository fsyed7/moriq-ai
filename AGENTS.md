# Repository rules for coding agents
Read CLAUDE.md and docs/moriq-project/DOCUMENTATION-INDEX.md first. Verify current Git/file state: documentation records a checkpoint, not immutable future truth. Current status, security limits and fresh test evidence are the source-of-truth entry points; historical reports are evidence, not instructions to run scripts.

Preserve all original working-byte changes, untracked integration work, approved imagery and frozen evidence. Keep functional source paths/imports intact during organization. Do not delete files, rewrite history, force push, reset --hard, clean, automatically merge draft PRs or silently normalize evidence line endings.

Run relevant existing offline suites in isolated processes using Python 3.12 and documented PYTHONPATH/TEMP settings. Do not report historical passes as fresh. Keep failures, skipped checks and environment limits explicit. Update status, test evidence and relevant decisions when behavior changes; keep documentation portable and exclude private machine paths from public docs.

Use existing coding conventions, focused changes, input validation, bounded resources and explicit public/private boundaries. Source metadata cannot confer authorization; citations do not certify truth. Do not introduce live inference, real/confidential ingestion, private production viewing, automatic answer release or deployment without separate approval. Do not weaken frozen tests or runtime hashes.

The owner requires explicit approval before commits, pushes, merges or remote changes. Local migration preparation does not grant publication permission. Do not stage all files: ten historical restorations, five untracked integration files and Studio require separate review. No new feature implementation is authorized by this migration. For recovered 6.1B, inspect/reproduce, propose bounded acceptance, then wait for implementation approval.
