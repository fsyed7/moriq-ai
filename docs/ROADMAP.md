# MORIQ AI — Two-week V0.1 roadmap

Status: agreed V1 product direction recorded from the [PR #9 review](https://github.com/fsyed7/moriq-ai/pull/9#issuecomment-6026177279), October 6, 2026. These are requirements, not claims of implemented functionality.

The planning window is **October 6–19, 2026**, with the **V0.1 demo on October 20, 2026**. The roadmap works toward the agreed V1 pillars: MORIQ Knowledge, Architectural Intelligence, and MORIQ Guide/Freshie. The phase allocation below is a working plan, not a claim that implementation is complete or a new internal policy.

| Window | Focus | Intended outcome/status |
| --- | --- | --- |
| Week 1: October 6–12 | Foundation and public-first knowledge | Preserve upstream baseline/history and publishing safeguards; finish build/runtime validation; curate architectural knowledge and verify legitimate public MORIQ sources; record provenance, rights, and jurisdiction/edition metadata |
| Week 1: October 6–12 | Define demonstration cases | Select a narrow example for each pillar; define expected source evidence and non-fabrication behavior; choose an initial provider/model while retaining a provider-agnostic strategy |
| Week 2: October 13–19 | V0.1 behavior and evaluation | In subsequent implementation work, exercise cited answers, jurisdiction-aware guidance, and Freshie terminology/workflows/coordination/checklists/mistakes/next steps; evaluate missing-evidence and source-conflict cases |
| Week 2: October 13–19 | Demo readiness | Resolve blocking defects, verify runtime, review source use and known limitations, and rehearse the selected scenario |
| October 20 | V0.1 demo | Demonstrate the selected scope across the three pillars; distinguish delivered behavior from remaining V1 work |
| Later approved phase | Private/internal knowledge | Add only approved data after defining access, retention, and handling controls; no private ingestion is authorized by this roadmap |

## Current status and constraints

The upstream baseline and documentation branches are published. PR #9 remains unmerged; the current follow-up corrects documentation only. Full baseline build/runtime validation is still outstanding. No V1 capability or source ingestion is claimed complete.

The product direction is agreed; exact corpus, demo script, model configuration, supported jurisdictions, and evaluation thresholds still need selection. V1 release timing beyond the V0.1 demo is not specified. Preserve Open WebUI branding, attribution, notices, and licenses; no redesign or rebranding is part of this correction.
