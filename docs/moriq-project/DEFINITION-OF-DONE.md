# Definition of done
Every future task needs a bounded problem statement, explicit in/out-of-scope interfaces and frozen acceptance criteria before implementation. Completion requires relevant passing tests with retained failed attempts, security review where boundaries change, documentation updates, source/evidence integrity checks and no unintended edits. Record the exact environment and limitations; distinguish methods, subtests and acceptance IDs.

A reviewed Git checkpoint requires the owner's separate commit/push approval. Human acceptance and release approval remain separate from automated checks. Do not close a task when required code is missing, errors remain unexplained or approval is inferred. Offline prototype completion never implies production readiness.
