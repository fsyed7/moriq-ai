# Security boundaries and limitations
This is a trusted-host offline prototype. Do not enable live providers, ingest real/confidential sources, deploy, release generated answers automatically, expose private review endpoints or enable disabled adapters as part of migration.

Source metadata cannot grant approval. Separate authors and independent reviewers approve hash-bound source bytes and provenance; request-specific applicability is a later independent gate. Citation validity checks identity and consistency, not claim truth. Retrieved instructions remain untrusted content. Source approval does not authorize answer release.

The source gate projects fixed public categories; generated drafts belong only in an explicitly trusted reviewer channel. Attestations bind registry identity, request context and applicable source state. Frozen adversarial and H15 evidence must not be edited to make failures disappear.

Production blockers include real scoped identities, protected durable audit and keys, secure recovery, cross-process lifecycle/revocation, transport/storage protection, provider response/cancellation/idleness contracts, qualified architectural review, source rights and release ownership. Test identities, object capabilities, volatile state and one-process locks are not substitutes.

6.1A clock mismatch is deliberately denied when local and UTC dates disagree. Do not weaken that behavior while changing setup. A reviewed clock policy belongs to later integration work. The recovered 6.1B test errors remain open.

Original Task 4 V12 independent acceptance remains unmet despite narrower owner-led offline acceptance. Real educational drafts and C01 remain unapproved and un-ingested. Historical D/J benchmark failures remain visible; later passing runs do not erase them. UI zoom, spoken screen-reader and physical-device testing remain outstanding. Full upstream build/runtime and complete V1 user flows are not freshly validated.
