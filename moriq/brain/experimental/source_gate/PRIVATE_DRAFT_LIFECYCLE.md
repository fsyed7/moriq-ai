# Synthetic private draft lifecycle

Task 4.4B is an offline, trusted-host demonstrator. It copies pinned synthetic fixture text only. It has no generator, worker, provider, network, persistence or viewing endpoint. It never calls Task 3's public/view methods. Existing historical regression harnesses remain separate.

The host creates `OfflinePrivateDraftLifecycle` with six distinct synthetic roles: SA (source author), IR (ingestion reviewer), AP (applicability proposer), QR (question reviewer), PV (private reviewer) and RA (request authority). Host fixture credentials are not production authentication. Host-only reviewer grant/revoke methods must never be exposed to callers. Bare identity strings, uploaded approval/version/hash fields and arbitrary draft text do not confer authority.

The owner constructs fresh RequestContextAuthority and OfflineKnowledgePreflight instances. It never accepts a shared authority. Public wrappers keep every authority mutation and private access decision under one owner lock. A request snapshot binds opaque ID, monotonic version and the exact canonical RequestV1 hash, independently checked against the owner's version/hash ledger. RA updates invalidate old drafts in that context. Identical updates are no-ops. Updates do not approve sources or question applicability. Restart is a new empty owner with a new session; no state import exists.

The trusted host uses source/applicability wrappers and the QR-only `prepare` control-plane method for independent evidence review. IR must also grant a bounded source lease. `begin_fixture(fixture_id, request_id, ids)` snapshots the exact approved bundle, versions and leases. `complete_fixture` revalidates and retains the pinned fixture only. A host grant authorizes the exact held draft to PV. `request_view` and `view_fixture` authenticate PV and recheck current request, evidence, leases, grant and one-use permit. Citation structure is checked, never represented as claim verification.

Private success contains text, aliases and opaque draft ID, with `synthetic=true`, `claim_status=not_assessed`, `release_allowed=false`. Public projection is always the same withheld bytes. Private denial is always the same denied bytes. Control-plane source/bundle results are host-private, not public responses. Programmer configuration errors may raise a generic ValueError before an owner is created.

Revocation/update before private authorization denies. A private copy authorized first may return; a later revocation cannot recall it. The owner lock serializes these events only under exclusive host ownership. A reader admission flag rejects concurrent readers; waiting lifecycle writers prevent subsequent reader admission. No distributed consistency, protection from malicious Python or forced erasure is claimed.

Audit is volatile metadata only. An intent append must succeed before mutation/copy. Private response construction and final clock checks precede the final built-in committed-event append. Audit exceptions can leave an intent but cannot return a successful copy; uncertainty poisons the session. No fallback audit store or recovery exists. This is not durable protected audit. Exception text, draft/source/question text, credentials and permits are excluded from the audit and private errors.

Expiry uses the host UTC clock and checks agreement with Task 3's date source. Clock regression/disagreement/rollover poisons the owner. Source leases are at most seven days; drafts at most 300 seconds; permits at most 30 seconds, further capped by authority deadlines. Task 3's inclusive date expiry is unchanged. Existing preflight caps apply, including 16 references. Additional limits: 32 request contexts, 32 draft/reservation records, 64 cumulative permits, 256 owner operations, 2,048 audit events, 64 KiB fixture text, 128 KiB private response, 16 credentials and 32 fixture definitions. Failed operations do not refill budgets.

The frozen B01–B44 rows are retained verbatim in `private_draft_lifecycle-v1.json`, with original, addendum and composite specification hashes. The tests add request-authority cases; original K01–K52 and historical H15 expectations remain unchanged. Test-only corruption and fault injection are not runtime mutation APIs.

Production remains blocked on real identity, protected transactional lifecycle/audit, cross-process revocation, transport/storage security, secure recovery and qualified semantic review. Even the synthetic prototype is not ready for commit approval until every required regression gate passes; see the external Task 4.4B implementation report for actual results.
